# Security policy

This foundation is not suitable for hostile-source execution or sensitive
production auditing. Dynamic execution and remote adapters are disabled.

For a vulnerability, contact the maintainer privately through an independently
verified channel. Do not create an issue containing credentials, proprietary
source, or exploit payloads. No reporting endpoint or response SLA is invented
here; the maintainer must designate one before public distribution.

Integrity, sandbox escape, misleading assurance, leaked oracles, and licensing
violations can all be blocking defects. Record suspected issues in the finding
register using D1-D4 as defined in the methodology. Preserve evidence, quarantine
affected capability, revoke affected claims, then use an audited corrective
package. Do not delete inconvenient or negative records.
