# Requirements, traceability and baseline control

Every normative requirement has a stable ID, source/clause, rationale, owner,
verification method, evidence references, governing package and implementation
status. DRAFT is not approved; IMPLEMENTED is not independently VERIFIED.
No orphan mandatory requirement or untraceable implementation is accepted.

Machine-readable requirements currently cover foundation behavior and governing
constraints. They are a seed for WP-002, not an assertion that the plan's full
requirements derivation is complete. WP-002 must expand accessibility,
performance, privacy, interoperability, numerical semantics and runtime evidence
with independent ambiguity review.

An approved baseline identifies version/commit, content digest, owner, approval,
scope and replacement rules. Dependencies must be closed before activation
unless an explicit approved exception names compensating controls.
Freeze thresholds, metric definitions, seeds, denominators, budgets and exclusions
before affected experiment execution. Later changes create a new protocol,
retain the previous record and clearly separate exploratory outcomes.

The foundation validator checks IDs, schemas, references, active-package count,
dependency graph, required session records, local-only policy, and conservative
closure barriers. It does not infer authority from prose, validate all social
independence, evaluate scientific power, or certify regulatory compliance.
